# Plan, then approval

1. For a feature or bigger change, make a plan first (plan mode, or a `PLAN.md` file) and wait for the user's approval. If the guard says no plan is approved, write `PLAN.md` and ask the user to approve it. Do not work around the guard.
2. Use auto mode only after the plan is approved. Plan mode first, then auto mode, never the other way round.
3. After approval, do only what the approved plan covers. Anything outside it needs a new approval.
4. When the guard asks about a command, say the exact command and the reason, then wait for a yes. A yes covers that one command only. Read-only commands (`ls`, `cat`, `grep`, `git status`, `git diff`, `git log`) need no question.
5. Ask one clear question at a time. Do not stack options.
6. When the work is done, say what changed and what was not verified.
